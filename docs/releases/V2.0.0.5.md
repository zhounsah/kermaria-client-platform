## Scope

This release delivers Storefront lot A:
- `/services` is now a customer-need/problem router before the technical service catalog;
- six structured problem entry points route to the relevant service or educational resource;
- the four service universes remain the second navigation level, including `Support & IT`;
- the hero no longer injects `Comparer les formules`;
- redundant legacy sections are removed from the public landing;
- `storefront:services` supports structured `problemEntries` with frontend and backend validation;
- the existing legacy CMS JSON remains readable through a deterministic transition fallback and will be normalized on the next normal CMS save;
- dedicated regression contracts cover the new landing and the current `/ressources` hub UX.

## Deployment incident and rollback proof

The first SRV-13 cutover attempt used an API package built with plain `dotnet publish`. Because the project sets `<UseAppHost>false</UseAppHost>`, that package did not contain `Kermaria.ApiInternal.exe` and the Windows service could not start (`ERROR_FILE_NOT_FOUND`).

The v2.0.0.4 runtime was immediately restored from the pre-cutover backup and readiness returned 200. The API package was then rebuilt with the production command:

```powershell
dotnet publish apps/api-internal/Kermaria.ApiInternal.csproj -c Release -r win-x64 --self-contained false -p:UseAppHost=true -o out/api-internal
```

The corrected artifact contained the AppHost, the second cutover succeeded, and all API health checks returned 200.

This incident confirms that the AppHost check is a mandatory release gate for SRV-13.
