## Scope
WEBPORTAL-only security hotfix closing the audited CSRF gap on authenticated mutations:
- common portal mutation helpers enforce the existing double-submit CSRF token model;
- authenticated mutation routes that bypass the common portal BFF are explicitly guarded;
- two direct admin subscription mutation routes are explicitly guarded as well;
- browser-side authenticated mutations use `requestBffJson` / the common client helper so the CSRF header is attached automatically;
- public unauthenticated endpoints such as login, signup, contact and quote creation remain outside the authenticated CSRF requirement;
- no API-INTERNAL implementation change and no SQL migration are part of this release.

## Known follow-up
`/api/formules/souscrire` currently parses and validates the checkout payload before checking the CSRF token. Its internal session validation and mutation remain behind the CSRF guard, so a request cannot reach the authoritative checkout mutation without a valid token. For consistency and lower pre-auth processing, the CSRF check should nevertheless move before JSON/business-payload validation.
