## Scope
This release redesigns the Billing V2 administration catalog and adds a focused UX polish pass. It does not change the SQL schema, Billing V2 pricing authority, subscription lifecycle, payment lifecycle, or provisioning semantics.
## User/admin-visible changes
- `/admin/catalog` is now a searchable/filterable business catalog view.
- Services, formulas and commitments use dedicated editor pages with addressable tabs.
- Tariff administration moved into the relevant service/tier context.
- Providers are presented as `Integrations`.
- Service and tier creation are available from the new catalog UX and create safe inactive/non-public records.
- Formula composition has a dedicated editor and server-backed commercial preview.
- Price history and new immutable price versions are presented separately.
- VAT and discounts are entered as human-readable percentages.
- Sticky save/cancel actions and unsaved-change protection are available on the main editors.
- Unsaved-change protection also covers price revision, formula component and provider-mapping subforms.
- The `Retirer` formula-component action now uses the normal destructive button styling.
- The admin `A partir de` amount ignores inactive tiers.
- A new price revision pre-fills VAT from the current price matching the selected cadence + charge trigger; no arbitrary fallback VAT is invented.
## Backend scope
Two safe creation capabilities were added to the existing Billing V2 catalog administration service:
- `POST /internal/admin/billing-v2/catalog/services`
- `POST /internal/admin/billing-v2/catalog/services/{id}/tiers`
Creation defaults are fail-safe/inactive and use the existing audit/mutation pipeline.
No migration or DDL is part of this release.

## Rollback
There is no database rollback for this release because no schema/data migration was executed.
If rollback is required:
1. stop `KermariaApiInternal`;
2. restore the retained pre-v2.0.0.2 API runtime;
3. repoint `/opt/kermaria/webportal` to the retained `v2.0.0.1` release;
4. restart both services;
5. verify private and public readiness.
Do not remove the retained runtime/release until the release has had adequate production soak time.
## Known non-blocking debt
