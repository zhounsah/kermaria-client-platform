# V1.3 - Plateforme éditoriale administrable

> Historical domain note - 2026-08-20: zacharyhounsa.ovh names in this document describe the state of that release. Current canonical hosts are zachary-it.fr, dashboard.zachary-it.fr and administration.zachary-it.fr. See docs/DOMAIN_MIGRATION_2026-08-20.md.

## Architecture

La plateforme éditoriale ajoute un noyau commun pour trois contenus :

- `wiki_article` : articles du centre d'aide public ;
- `seo_page` : pages publiques dynamiques à slug racine ;
- `faq` : questions/réponses réutilisables par scope.

Le contenu vit en MariaDB dans `editorial_contents`. Le Markdown reste la source
éditoriale. Les pages publiques et le back-office passent par le webportal/BFF,
puis par l'API interne ; aucun accès direct à MariaDB n'est fait depuis Next.

## Back-office

Navigation :

- `/admin/editorial/wiki`
- `/admin/editorial/seo`
- `/admin/editorial/faq`

Chaque section propose liste, recherche, filtres d'état, création, édition,
aperçu Markdown, import `.md/.markdown`, export Markdown, publication,
archivage et historique des versions.

Les catégories Wiki/FAQ sont administrables depuis les listes concernées.

## Markdown

Le rendu utilise `react-markdown`, `remark-gfm` et `rehype-sanitize`.

Support prévu :

- titres, paragraphes, gras, italique ;
- listes ordonnées/non ordonnées ;
- citations, code inline, blocs de code ;
- séparateurs ;
- tableaux GitHub Flavored Markdown ;
- liens internes et liens web sûrs ;
- images Markdown avec rendu responsive.

Le HTML brut est ignoré. Les URLs dangereuses sont filtrées au rendu.

## Import / export

L'import Markdown se fait côté navigateur dans le formulaire admin. Le fichier
n'est jamais publié automatiquement. Le frontmatter YAML simple peut alimenter :

- `title`
- `slug`
- `description`

L'export génère un `.md` avec frontmatter minimal.

## Publication et révisions

États :

- `draft`
- `published`
- `archived`
- `scheduled`

Seuls les contenus `published` avec `publishedAt` apparaissent publiquement.
Une modification importante conserve un snapshot dans
`editorial_content_revisions`. Une version ancienne peut être consultée et
restaurée depuis le back-office.

## Redirections

Lorsqu'un contenu publié change de slug, l'ancien chemin est conservé dans
`editorial_redirects` et la route publique redirige vers le nouveau chemin.

## Wiki

Hostnames :

- canonique public : `wiki.zacharyhounsa.ovh`
- alias interne : `wiki.home.bzh`

Le proxy Next réécrit ces hostnames vers les routes internes `/wiki/*` sans
changer l'URL visible. Les canonical pointent vers `wiki.zacharyhounsa.ovh`.
Le hostname interne reçoit une directive `noindex` sur les pages Wiki.

Routes Wiki :

- `/`
- `/categorie/<slug>`
- `/article/<slug>`

## Pages SEO

Les pages SEO publiées sont servies sur le domaine principal par `/<slug>`.
Les slugs réservés empêchent de masquer les routes système comme `/admin`,
`/api`, `/offres`, `/signup`, `/diagnostic`, `/configurer`, etc.

Les pages `draft`, `archived` ou `noIndex` ne sont pas ajoutées au sitemap.

## FAQ

Les FAQ sont des contenus `faq` avec réponse Markdown. Les scopes permettent de
réutiliser une entrée sur plusieurs contextes (`global`, `offres`,
`diagnostic`, etc.). Le composant public commun ne rend rien si aucune FAQ
publiée n'existe pour le scope.

Le schema `FAQPage` n'est pas ajouté automatiquement : Google ne montre plus le
rich result FAQ depuis mai 2026. Il devra rester explicite si réintroduit.

## Permissions

Permissions prévues :

- `content.wiki.read`
- `content.wiki.write`
- `content.seo.read`
- `content.seo.write`
- `content.faq.read`
- `content.faq.write`
- `content.publish`

La table `admin_permission_grants` stocke les grants. Tant qu'aucun grant
n'existe pour une permission, les administrateurs internes existants gardent un
accès d'amorçage ; dès qu'un grant existe pour une permission, seuls les
utilisateurs explicitement accordés la possèdent.

## Limites V1.3

- Pas de faux articles, pages SEO ou FAQ réelles livrés.
- Pas de moteur Elasticsearch/Meilisearch.
- Pas de DAM complet ; les images Markdown par URL sont préparées seulement.
- Le cache reste dynamique/no-store pour garantir une publication rapide.
