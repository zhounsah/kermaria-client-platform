publiee autour du tag Git `v1.0.0`.

## Verite de reference

- Le tag Git `v1.0.0` existe et pointe vers le commit de release
  `7d473480e697cd72c05e56d63c212ebc997f59d7` date du `2026-07-31`.
- Certains manifests techniques restent encore en `0.1.0`
  (`package.json` racine et `apps/webportal/package.json`).
- Pour cette version, la verite de reference est donc :
  - le tag Git `v1.0.0` ;
  - l'etat reel du depot ;
  - les garde-fous de [`../AGENTS.md`](../AGENTS.md).

Ne pas deduire la version fonctionnelle de la plateforme a partir des seuls
champs `version` des packages.

## Perimetre 1.0.0

Le site au sens Kermaria couvre la plateforme complete :

- la vitrine publique et les parcours anonymes ;
- l'espace client authentifie ;
- le back-office interne ;
- le BFF `Next.js` dans `apps/webportal` ;
- l'API privee `ASP.NET Core` dans `apps/api-internal` ;
- MariaDB, Active Directory, paiements, contenus administrables,
  telechargements clients et KoXo.

Frontiere a ne pas casser :

```text
browser -> WEBPORTAL / BFF -> API-INTERNAL -> MariaDB
```

`WEBPORTAL` ne contacte jamais MariaDB, AD, NAS, RDS, VPN ni BPCE
directement.

## Distinction importante entre les types de docs

- Etat actuel : documents qui decrivent le comportement present dans le depot.
- Procedure operatoire : lancement, validation, deploiement, rollback,
  sauvegarde.
- Historique : documents V0.xx qui expliquent quand et pourquoi un lot est
  apparu.
- Futur / partiel / spec : documents de cadrage ou d'alignement qui ne doivent
  pas etre lus comme deja entierement livres.

Les dossiers `docs/v0.38/` et `docs/v0.40/` contiennent de la valeur, mais
doivent etre lus avec cette distinction en tete.

## Scripts et controles utiles

- installation : `npm install`, `dotnet restore`
- verification web rapide : `npm run typecheck:webportal`,
  `npm run lint:webportal`
- verification web complete : `npm run check:web`
- validation globale : `npm run validate`
- smoke API : `npm run test:api`
- health checks : `npm run check:health`

Les details et preconditions sont centralises dans
[`OPERATIONS.md`](OPERATIONS.md).

- Ne pas traiter tous les documents V0.xx comme strictement actuels sans
