# Storefront Phase 2 — catalogue services administrable

## Périmètre

Cette phase rend administrables les pages publiques suivantes :

- `/services`, `/tarifs` et les quatre catégories de services ;
- quinze pages de services SEO sous `/services/<slug>`.

`/formules` reste un parcours d'offres configurables distinct et n'est pas
modifié par cette phase.

## Architecture éditoriale

Le registre fermé `ManagedContentKey` inclut le type `storefront_page`. Les
contenus sont persistés dans `managed_content_entries`, sans nouvelle table ni
migration. Une page storefront est un JSON validé côté API, conservé dans
`body_markdown` uniquement pour réemployer le même audit, les mêmes droits,
CSRF, BFF et garanties de seed idempotent que les contenus administrables
existants.

Le formulaire `/admin/content/[key]` reconnaît ce type et édite des champs
structurés : H1, lead, SEO, CTA, sections, FAQ et liens associés. Les clés,
URLs et types restent verrouillés par le registre.

## Prix

Le contenu storefront ne porte aucun montant. La validation API refuse un
montant exprimé en euros afin d'empêcher un second catalogue tarifaire.
`/tarifs` affiche, lorsque disponible, une projection en lecture seule du
catalogue Billing V2. Les pages utilisent "Sur devis" lorsque cette projection
est indisponible ; Billing reste l'autorité des montants et de la commande.

## Seeds et sécurité

`StorefrontContentSeed` fournit le contenu initial complet des 21 pages. Le
seed passe par `SeedMissingAsync`, donc une modification enregistrée depuis
l'administration n'est jamais écrasée. Les CTA et liens sont limités à des
routages internes, et le rendu long passe par `ManagedMarkdown` sécurisé.

## Validation

Les smoke tests API vérifient le seed, lecture publique, droits admin,
persistance d'une mutation structurée, restauration et refus d'un montant.
Les contrats web vérifient le registre, les pages, l'administration, le
sitemap et les métadonnées.
