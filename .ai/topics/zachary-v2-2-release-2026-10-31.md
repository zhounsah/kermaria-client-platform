# Zachary IT v2.2 — état de livraison au 31/10/2026

La branche `codex/release-v2.2.0` réunit la refonte publique et les six paliers Assistance Billing V2. Les paliers particuliers sont limités à une unité pour le foyer ; les professionnels autorisent 1 à 10 postes. Le propriétaire a choisi le libre-service et demandé l'ouverture du Checkout pour tout le catalogue éligible, avec engagements FLEX, 6 et 12 mois. Les modalités Assistance approuvées figurent dans `docs/ASSISTANCE_CONDITIONS_V2.2_PROJET.md` et dans le seed des CGV. Une mise à jour du seed ne republie pas les CGV déjà stockées en base.

La candidate a été déployée sur DEV : migrations 106–107 appliquées sur `kermaria_dev`, API `ac2a8a6` et Web `a8f290d` sains, six liens/prix vérifiés au navigateur à 390/1440 px, quote Pro Business × 2 à 93,60 € TTC mensuels, Pro × 11 et particulier × 2 rejetés. Le correctif de chargement de l'accueil a été contrôlé sur vingt chargements rapides : un seul H1 visible ; trente combinaisons de pages/largeurs 320–1920 px passent. Les CGV v2.2 ont été publiées sur DEV via le BFF après sauvegarde et relecture de la page publique. Le propriétaire a demandé de limiter la recette DEV à des étapes sans pièce fiscale parce que BPCE y est configuré en live ; la readiness DEV refuse également le Checkout taxable avec `BILLING_V2_BPCE_SELLER_IDENTITY_UNVERIFIED`. Aucun paiement Stripe complet ni émission BPCE n'a été testé. PR brouillon : `https://github.com/zhounsah/kermaria-client-platform/pull/2`.

Lighthouse mobile 13.6.0, deux passes séquentielles sur RDC-07 : PROD v2.1.1-hotfix.5 performance 47/46, LCP 13,38 s, CLS 0,911 ; DEV candidate performance 71/73, LCP 6,04/6,03 s, CLS 0,021. Accessibilité 100 dans les quatre passes. Le SEO DEV 69 est lié au `noindex` intentionnel. Ces chiffres sont de laboratoire ; aucune mesure INP terrain. Le doublon d'en-tête `X-Robots-Tag` DEV a été supprimé au vhost Nginx SRV-11 en masquant celui de l'amont, après sauvegarde et test de configuration ; DEV reste non indexable, PROD indexable. Le Web DEV final n'émet plus `X-Powered-By`. Voir le dossier de release pour les conditions et limites.

PROD est restée sur Web `v2.1.1-hotfix.5-dfc31c5-prod` avec Checkout API/BFF fermé lors du dernier relevé. Les CGV v2.2 approuvées ont été publiées via le BFF sur PROD après sauvegarde de la version antérieure, puis relues sur `/cgv` ; aucun binaire, migration ou drapeau de paiement PROD n'a changé. Les migrations 103–107 sont absentes de `kermaria` ; aucun service Assistance n'y est présent. Le Checkout global rendrait aussi achetables les huit services directs et quatre presets déjà publiés. Le tableau de readiness PROD expose une revue humaine KoXo avec un texte statique périmé : le fournisseur HTTP est câblé et sa configuration est présente, mais l'application réelle des quotas sur une cible client reste à prouver. Le libellé est corrigé dans la candidate. `npm run backup:mariadb` échoue sur une vue invalide ou les droits `SHOW VIEW` ; un dump de tous les objets accessibles hors cette vue est conservé, sans restauration éprouvée. Avant ouverture, reprendre les portes de validation, les preuves et le plan de retour arrière de `docs/releases/V2.2.0.md`, notamment sauvegarde PROD complète et preuve de livraison du catalogue éligible.

Les artefacts Web `.tar.gz` et API `.exe` de PROD ont été préparés depuis `6daad5b`, avec empreintes et retour arrière dans `docs/releases/V2.2.0.md`. Ils ne sont pas installés. Deux choix du propriétaire sont en attente : poursuivre les migrations avec le dump vérifié hors vue invalide, et confirmer la livraison manuelle du stockage ou le garder fermé tant que l'application des quotas KoXo n'est pas prouvée.
