V0.35 « panier / commande groupée à la carte » **implémenté sur `main` le 2026-07-08** (doc `docs/V0.35_CART_ALACARTE.md`, jalon ROADMAP mis à jour, `npm run test:cart`).

Décisions tranchées avec l'utilisateur (l'échange, pas le doc de cadrage qui était « à cadrer ») :
- Panier self-service → **document commercial payable direct**, **sans approbation admin**. Confirmation = crée UN `commercial_document` multi-lignes (`origin='client_cart'`, migration `028_alacarte_cart.sql`, table `cart_items`) puis l'**émet aussitôt** (BPCE mock en phase de tests) pour le rendre payable.
- **3 rails** : Stripe, PayPal (`PayButton`) **et virement** (bloc V0.21) — aucun nouveau rail/code de paiement, on réutilise le document généré.
- Panier **strictement one-shot** : offres `commercial_offers` cadence `one_time` actives prix>0 ; récurrent refusé (`CART_OFFER_NOT_ELIGIBLE`).
- **Provisioning « le cas échéant »** au règlement (tous rails convergent sur `InvoiceIssuingService.ConfirmPaymentAsync`, gate `origin='client_cart'` → `CartProvisioningTrigger` → `ReconcileAsync`). **Révise le garde-fou de cadrage** « aucun provisioning déclenché par le panier ».

**Point important / honnête** : le provisioning du projet est piloté par les **abonnements** (V0.31 : offre recurring → groupe AD). Le panier étant one-shot et aucune offre one-shot ne mappant de groupe, ce hook est **inerte aujourd'hui** (no-op audité `cart.provisioning.skipped`) — câblé pour l'avenir mais ne provisionne rien pour le catalogue courant. Si l'utilisateur veut qu'un achat one-shot donne un accès, il faut ajouter un mapping offre one-shot → ressource (hors V0.35).

Convention repo réutilisée : la matérialisation document = **chemin MariaDB uniquement** (mock `CreateCartDocumentAsync` throw `NotSupportedException`, comme la facturation d'abonnement). Le contrat test `verify-cart-contract.mjs` est **statique** (assert sur le source), comme tous les `verify-*-contract.mjs`. Reste à recetter le chemin confirm→émission→paiement→provisioning sur MariaDB + BPCE mock + Stripe test/PayPal sandbox.

Vérifs passées : `dotnet build` api-internal (0 err), `test:api` (smoke, l'app boot avec le nouveau DI), typecheck shared+webportal, lint webportal, test:cart, + test:commercial/payments/stripe/subscriptions non régressés. `test:bpce` était **déjà rouge sur main avant V0.35** (assert `/Facture émise/` absent de `formatters.ts`, non lié).
